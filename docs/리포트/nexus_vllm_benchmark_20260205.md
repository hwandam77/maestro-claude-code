### 3.2 동시 요청 (Aggregate Throughput)

| 동시 요청 | Wall Time | 총 토큰 | Agg TPS | 스케일링 | 최대 레이턴시 |
|----------|-----------|---------|---------|---------|-------------|

| 4 | 4.246s | 512 | **120.6** | 3.70x | 4.22s |
| 8 | 4.871s | 1024 | **210.2** | 6.45x | 4.85s |
| 16 | 5.839s | 2048 | **350.7** | 10.76x | 5.81s |
| 32 | 8.866s | 4096 | **462.0** | 14.17x | 8.84s |

**핵심 발견:**
- 32개 동시 요청에서 **462 tok/s** aggregate throughput
- 1→16 요청까지 거의 **선형 스케일링** (10.76x)
- 16→32에서 스케일링 효율 감소 (14.17x / 16 = 0.89)
- KV 캐시 23,184 tokens로 짧은 출력(128 tok)에서는 많은 동시 요청 가능

## 6. gpu-memory-utilization 튜닝 결과

| 값 | 결과 | KV 캐시 | 동시(16K) | VRAM 여유 |
|----|------|---------|----------|----------|
| 0.92 | **OOM** | - | - | - |
| 0.95 | 정상 | 2.74 GiB / 17,968 tok | 1.10x | ~950 MiB |
| **0.96** | **정상 (최적)** | **3.54 GiB / 23,184 tok** | **1.42x** | **~130 MiB** |
| 0.97 | **OOM** | - | - | - |

- 0.92 실패 이유: 70B AWQ 모델이 GPU당 ~20 GiB 사용, 0.92 * 24.576 = 22.6 GiB로 부족
- **0.96이 최적**: 0.95 대비 KV 캐시 29% 증가, 동시 처리 29% 향상
- 0.97에서 OOM → VRAM 여유 ~130 MiB가 한계선

## 8. Nexus vs Cognit 비교

| 항목 | Nexus (DeepSeek-R1-70B) | Cognit (Qwen3-Coder-30B) | 비율 |
|------|------------------------|--------------------------|------|
| **모델 크기** | 70B (dense) | 30B (MoE, 3B active) | 23x active params |
| **단일 TPS** | **33.7 tok/s** | **180 tok/s** | 0.19x |
| **VRAM 사용** | 24.0 GB / GPU | 11.3 GB / GPU | 2.1x |
| **KV 캐시** | 23,184 tok | 60,064 tok | 0.39x |
| **동시 8req Agg** | 210 tok/s | 1,080 tok/s | 0.19x |
| **동시 32req Agg** | 462 tok/s | N/A (max 8) | - |
| **GPU 온도 피크** | 73°C | 67°C | +6°C |
| **TPS 안정성** | 1.0% 변동 | 7.6% 변동 | Nexus 우위 |
| **gpu-mem 최적** | 0.96 | 0.93 | |
| **응답 품질** | 추론/reasoning 강점 | 코딩 특화 | 용도 상이 |

### 분석

1. **TPS**: Cognit이 5.3배 빠름 — 30B MoE(3B active)와 70B dense의 근본적 차이
2. **안정성**: Nexus가 더 일관적 (compute-bound로 메모리 병목 없음)
3. **동시 처리**: Cognit이 짧은 출력에서 유리, Nexus는 32개까지 동시 가능
4. **VRAM 효율**: 70B 모델이 VRAM 대부분 차지 → KV 캐시 부족
5. **용도 구분**: 빠른 코딩 → Cognit, 깊은 추론 → Nexus
