### 6.3 핵심 발견

**1. TPS 저하 패턴: 출력 길이 증가 시 점진적 감소**

| 구간 | TPS 범위 | 저하율 (10% 대비) |
|------|---------|-----------------|
| 10~30% (1,638~4,915 tokens) | 177~178 tok/s | 기준 |
| 40~60% (6,553~9,830 tokens) | 170~174 tok/s | **-2.3~4.6%** |
| 70~90% (11,468~14,745 tokens) | 164~171 tok/s | **-3.9~7.6%** |
| 100% (15,970 tokens) | 161 tok/s | **-9.4%** |

- 최고 TPS: **178.12 tok/s** (10%, 1,638 tokens)
- 최저 TPS: **161.42 tok/s** (100%, 15,970 tokens)
- 최대 성능 차이: **9.4%** (178.12 → 161.42)

**원인 분석**: KV 캐시 크기가 증가하면 GPU 메모리 대역폭 부하가 커져 attention 연산 속도가 저하됨. RTX 3080 Ti의 12GB VRAM에서 91.7%를 사용하므로, 긴 시퀀스에서 메모리 스왑/재배치 오버헤드 발생 가능. 100% 컨텍스트에서 약 10% 성능 저하는 이 하드웨어 제약을 감안하면 양호한 수준.

**2. 100% 컨텍스트 성공적 활용**

- max_tokens=16,256 (max_model_len - prompt_tokens - 1) 설정으로 98.2% 컨텍스트 활용
- 실제 출력: 15,970 tokens (98.9s), 161.42 tok/s
- 15,970 tokens에서 자연 종료 (stop) - 모델이 응답 완결

**3. 90% 테스트에서 자연 종료 (stop)**

- max_tokens=14,745로 설정했으나 9,467 tokens에서 자연 종료
- 모델이 응답을 완결한 것으로, 실사용 시 max_tokens를 크게 설정해도 필요 이상 생성하지 않음

**4. GPU 온도 추이**

- 유휴 상태: 28°C / 26°C
- 연속 부하 피크: **67°C / 62°C** (40% 테스트 시점, 누적 부하)
- 안정화: 52~59°C (이후 테스트)
- 임계값(80°C) 대비 **최소 13°C 여유** → 장시간 연속 추론에도 안전

### 강점

1. **안정적인 디코딩 속도**: 출력 길이에 무관하게 180 tok/s 유지
2. **우수한 동시 처리**: 8개 동시 요청에서 1,080 tok/s aggregate throughput
3. **낮은 레이턴시 변동**: 표준편차 < 15ms로 예측 가능한 응답 시간
4. **온도 여유**: 피크 부하에서도 42°C, 장시간 운영 가능
5. **MoE 모델의 효율성**: 30B 파라미터 모델을 24GB VRAM에서 AWQ로 효과적 운영

### 개선 가능 영역

1. **GPU 불균형**: TP 분산에서 GPU0 > GPU1 부하 차이 (99% vs 63%). 모델 아키텍처 특성일 수 있으나 모니터링 필요
2. **max-num-batched-tokens**: 현재 2048로 제한. VRAM 여유 시 증가하면 프리필 병렬성 향상 가능
3. **max-num-seqs**: 8개 제한은 소규모 동시 사용에 적합. 다수 사용자 시 증가 검토
4. **Prefix Caching**: 짧은 프롬프트에서 7-8% 개선. 긴 system prompt 활용 시 더 큰 효과 기대
